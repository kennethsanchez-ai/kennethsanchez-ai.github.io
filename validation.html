Evidence scope

This page summarizes recorded validation for the completed private v2.2.0 release. The release candidate passed 428 local tests, and the complete suite passed again before and after the release metadata commit. Focused version, reporting, and persisted-data security checks passed 114 tests. These are historical release results, not a new test execution or a live production assessment.

The underlying source, CI, release, and attachment records are private. This public summary deliberately provides no inaccessible CI links, release download links, credentials, infrastructure identifiers, or operational paths. Publicly readable documentation does not imply public application access.

What the automated tests cover

Reporting compatibility

Text and JSON stdout behavior, document schema, insertion order, timestamp precision, null evidence, and equivalence between stdout and explicit file output.

Export failure behavior

Exclusive creation, existing-file protection, missing-parent failure, UTF-8 LF output, silent success, and non-finite rejection before file creation.

Persisted-data boundaries

Malformed observations, safe warning fields, redaction of raw errors and transient identifiers, non-finite latency, and read-only database behavior.

Diagnostic semantics

Authoritative monthly counts versus bounded recent events, strict HTTP statuses, health ages, malformed or future timestamps, and trust/health separation.

Regression coverage also exercises recommendation tie-break rules, provider trust, quota behavior, registry contracts, and existing CLI workflows. Test success verifies the assertions and fixtures used; it does not establish correctness for every possible provider response.

Python and container CI

The v2.2.0 tag workflow completed successfully on Python 3.12 and Python 3.13. Both jobs installed the declared application/test extras, ran pytest, and ran Python compilation checks. The dependent container/build job also completed successfully. The workflow builds the container with image pushing disabled.

The released commit was fast-forwarded into main without a merge commit, squash, or rebase. Main CI succeeded on the same release commit. A subsequent documentation-only finalization commit also passed the Python and container jobs. These successful builds are not a deployment, a registry upload, or validation against live provider accounts.

Distribution and metadata validation

An isolated temporary source copy produced a v2.2.0 wheel and source distribution using existing build tooling. Both artifacts identified version 2.2.0; project/runtime version consistency, Python compatibility metadata, dependency syntax, declared extras, and both CLI entry points were checked.

Archive inspection confirmed the reporting package and all four PostgreSQL SQL package-data files. The source archive includes the README; the wheel carries its package description in metadata. Tests are excluded from the runtime wheel and retained in the sdist under the approved packaging policy. No actual credentials, databases, logs, caches, or unintended build/development directories were identified.

All 83 packaged source/data files were compared with the release source; content matched after normalizing Windows line endings. The sdist’s README and project metadata were checked as well. Packaging validation does not certify a live database deployment or migration execution.

Offline smoke tests and artifact integrity

Smoke tests imported the built wheel and ran Price Intelligence and Provider Status in text and JSON formats using isolated temporary configuration. Network access and search execution were blocked. Missing-database reporting created no database. File export matched stdout JSON byte for byte and passed silent-success, overwrite-rejection, and missing-parent checks.

The two validated distributions were uploaded as private GitHub release attachments, then downloaded into a separate temporary location. Their SHA256 hashes matched the approved local artifacts. Attachment names, sizes, and GitHub-reported digests were reconfirmed during release documentation finalization. The public website does not expose these private files or offer downloads.

The annotated release tag still identifies the original release commit. Main integration preserved that commit, while the later documentation-only commit did not move or recreate the release tag. These checks establish release identity and integrity independently of provider access.

Known limits and nonblocking observation

Source-distribution fixtures: the sdist omits the two JSON fixtures used by the Hotelbeds and KAYAK tests. Including tests in a source distribution is intentional policy; the missing fixture data means the archive is not a complete standalone test checkout. Full-suite validation uses the repository checkout. This limitation was reviewed and accepted as nonblocking; no packaging change was made for v2.2.0.

Not validated live: these results do not establish live KAYAK or Hotelbeds access, fresh hotel availability, production reliability, provider authorization, billing correctness, or successful booking. No provider was enabled as part of the release, and no application deployment or PyPI publication was performed.
