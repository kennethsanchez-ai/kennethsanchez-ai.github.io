What is implemented and who can use it

The private application includes a CLI for configured searches, monitoring, manual offers, history, comparison, reporting, and operational checks. These are implemented capabilities, not public web services. The examples below describe commands available in an authorized local installation; this website does not provide source access, credentials, package downloads, or live hotel inventory.

Existing capabilities include normalized offer comparison, deterministic recommendation ordering, profile-aware requests, guarded notifications, and compatible historical-price analysis. v2.2.0 specifically adds JSON file export, persisted quota activity, health ages, and consolidated reporting serialization.

Verified command groups

Profiles and source inspection
profiles, profile-show, and sources inspect available configuration or source catalog information. profile-use changes the selected profile.
Manual offers and browsing
manual-template, manual-import, and manual-add support user-confirmed offers. search-links lists user-assisted source links; browser-opening options open ordinary pages rather than scraping them.
History and comparison
price-history and compare-offers review persisted observations and latest offers. Price Intelligence adds evidence about savings, compatible history, freshness, volatility, and confidence.
Search and monitoring
scan runs a configured scan. run, pause, resume, and stop support monitoring control. These workflows are not the read-only reporting path.
Operational checks
self-check and backup-verify inspect configuration or backup readiness; they are not certification of a production deployment.

The CLI supports --profile for profile selection. --format json is limited to Price Intelligence and Provider Status. --output is limited to Price Intelligence JSON; it is not a generic export flag for other commands.

Price Intelligence: text, JSON, and file export

These examples are verified against the CLI parser and reporting tests:

hotel-deal-hunter-public price-intelligence
hotel-deal-hunter-public price-intelligence --format json
hotel-deal-hunter-public price-intelligence --format json --output report.json

The first two forms existed before v2.2.0. The third adds explicit file output with the same JSON document as stdout. Schema version remains "1". The document distinguishes no database, no current offers, and available-offer results; unavailable historical evidence remains explicit rather than fabricated.

  • File creation is exclusive: an existing file causes failure without overwrite.
  • The parent directory must already exist; no directories are created automatically.
  • Serialization completes before file creation, so serialization failure creates no export file.
  • Exports use UTF-8, LF line endings, and exactly one trailing newline.
  • Successful file output is silent on stdout. Without --output, JSON is emitted to stdout.

Compatibility and confidence describe recorded evidence. They do not predict availability or guarantee a future booking price.

Provider Status: observation, not enforcement

hotel-deal-hunter-public provider-status
hotel-deal-hunter-public provider-status --format json

Provider Status combines provider descriptions with persisted health and quota activity. It makes no provider calls, does not construct the search engine, does not refresh usage from an external service, and does not initialize a missing database.

usage_count
Authoritative recorded-event count for the current UTC month, queried independently of the recent event sample. It is not a provider’s billing statement or remaining allowance.
recent_event_count
That provider’s event count within the latest 100 persisted events across providers. It is bounded and can be lower than monthly usage.
Latest quota event
A valid recorded timestamp, success flag, and HTTP status may be displayed. HTTP status accepts integers from 100 through 599 and rejects booleans, numeric strings, and floats.
No inferred quota state
The report’s quota configured, state, limit, and remaining fields remain null. Unsupported quota and unavailable persisted activity have explicit source labels.

Health ages and serialization guarantees

last_attempt_age_seconds and last_success_age_seconds describe persisted timestamps relative to report generation. Unavailable, invalid, or future timestamps yield null. There is no stale-health threshold implied by an age, and diagnostics do not change trust or production eligibility. This differs from Price Intelligence’s separate offer-freshness classification.

Reports use UTC timestamps ending in Z at whole-second precision. Aware timestamps normalize to UTC; the pre-existing naive-as-UTC convention is retained. JSON uses two-space indentation, insertion-order fields, strict rejection of NaN and Infinity, and one final newline. These shared mechanics do not add or remove report fields.

Operational safeguards and limits

Malformed persisted data is filtered through safe parsing and allowlisted warnings. Reports exclude raw error text, credentials, source endpoints, and transient provider identifiers. Stable warning row identifiers may remain when part of the report schema. Non-finite persisted latency is treated as unavailable.

For scan dry-run, the verified syntax is hotel-deal-hunter-public scan --dry-run. It suppresses persistent writes and notification delivery, but it may still invoke configured providers. It is not an offline mode. No scan, live provider, or notification workflow was exercised for these public pages.

v2.2.0 does not change provider activation, eligibility, ranking, quota enforcement, database schema, or API contracts. Implemented safeguards and automated tests do not establish live provider validation or a production deployment. See validation evidence and completed versus planned work.
